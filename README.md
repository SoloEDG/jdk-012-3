# 余境 · 虚拟艺术馆

沉浸式三维线上展览。支持**策展包交换**：在浏览器中导入另一场展览的策展包
（作品图片、摆放、主题路线、讲解资源），预览确认后原子切换，并可再次导出交换。

安装：`npm ci`
本地启动：`npm run dev`
Docker 启动：`docker compose up --build`，访问 http://localhost:18112 。

测试：`npm test`（单元/集成，vitest）· `npm run test:e2e`（端到端，playwright）· `npm run typecheck`

---

## 策展包格式（yujing-pack/1）

单个 JSON 文件（建议后缀 `.yujingpack.json`）：

```jsonc
{
  "format": "yujing-pack/1",
  "exhibition": { "id": "…", "title": "…", "en": "…", "intro": "…",
                  "space": { "width": 12, "depth": 16 } },
  "artworks": [{
    "id": "b1", "title": "…", "en": "…", "artist": "…", "year": "…",
    "medium": "…", "color": "#…", "description": "…", "duration": 40,
    "place": { "x": -5.4, "z": -4, "facing": 1.5708, "w": 2.13, "h": 2.73 },
    "imageRef": "sha256:…",        // 作品身份 = 图片内容哈希
    "sameAs": ["sha256:…"]          // 可选：策展人显式声明的身份别名
  }],
  "routes": [{ "id": "r1", "name": "…", "subtitle": "…", "stops": ["b1"] }],
  "narration": [{ "artwork": "b1", "transcript": ["…"], "audioRef": "sha256:…" }],
  "assets": [{ "hash": "sha256:…", "mime": "image/png", "bytes": "<base64>" }]
}
```

所有资源按内容寻址（SHA-256），导入时逐字节校验。

## 两阶段导入：确认前旧展始终完整可参观

```
idle → reading → decoding → preview → committing → done
              └──── cancel / fail ────┘→ idle（旧展不受影响）
```

- **暂存隔离**：解码核验通过的资源写入按会话隔离的暂存区；当前展览的
  资源被钉住，任何导入路径都不会触碰。图片解码成功 ≠ 整包可用 ——
  还需通过哈希校验、引用完整性、空间与容量检查。
- **导入前预览**：容量（需写入/可复用/将回收）、缺失资源、路线引用、
  空间冲突（重叠/越界/与固定设施冲突）、讲解可用性、收藏与参观记录的
  身份迁移预览。存在 error 级问题时无法确认。
- **原子切换**：确认后，归档旧展 + 写入新展与资源 + 清理暂存 +
  切换 active 指针 + 记录迁移日志，全部在**同一个 IndexedDB 事务**内
  完成；事务末尾做容量不变量检查，失败即整体回滚。
- **讲解可降级**：讲解文本缺失/音频损坏只产生警告，对应作品以
  “讲解暂不可用”状态导入；图片资源损坏则是错误，整包不可导入。

## 作品身份规则：内容即身份

- 作品身份 = **图片内容的 SHA-256**。收藏、参观记录、笔记都以身份键存储。
- 切换展览时“迁移”= 在新展览的身份索引上重新解析：
  内容哈希完全相等 → 同一作品；策展人 `sameAs` 显式声明 → 同一作品；
  其余一律不合并 —— **名称相同但内容不同的作品绝不误合并**。
- 无法解析的收藏保持“归档”状态（数据保留、标题可辨、笔记可续写），
  绝不指向别的作品；重新导入对应展览后自动恢复。
- 解码期间新增的收藏/参观记录同样生效：迁移键在 commit 时刻重新读取。
- 每次切换写入可审计的迁移日志（迁移/归档各多少、依据的规则）。

## 容量上限与恢复行为（可观察）

- 显式预算（默认 12 MB，面板可调），容量条实时显示
  当前展览（钉住）/ 导入暂存 / 归档（可回收）/ 空闲。
- 回收顺序：暂存区（取消/失败即清）→ 归档展览按 LRU（只释放其独占资源，
  共享资源随引用计数保留）→ 仍不足则导入失败并给出确切缺口。
- 大资源尽早释放：解码逐资源进行并即时释放 base64 字符串与位图；
  引用计数归零的资源立即删除。
- 失败恢复：任何失败/取消后旧展完整可参观；崩溃遗留的暂存数据在
  下次启动时清除；当前展览资源残缺时自愈回退到内置展览并记录事件 —
— 任何时刻都不会出现新旧资源混搭。

## 并发与边界情况

- 每次导入分配单调递增会话号，每个 await 后校验会话有效性：
  **取消后迟到的解码结果直接丢弃**；连续开始两个导入时前者被取代，
  其暂存与结果不会混入。原子提交进行中不可取消、不可抢占。
- 重新导入同一展览（同 id）= 正常刷新，资源引用计数不泄漏；
  重新导入已归档/已回收的展览 = 从包文件完整恢复。
- 重新打开页面：启动时清理遗留暂存、加载唯一 active 展览、
  校验完整性，收藏解析只对当前展览生效。

## 代码结构

```
src/shared/exchange/      交换核心（纯逻辑，可单测）
  types.ts                包格式 / 报告 / 迁移日志类型
  packFormat.ts           结构校验与序列化
  validate.ts             引用 / 空间 / 容量 / 身份预览
  identity.ts             作品身份规则
  capacity.ts             容量策略（LRU 回收规划）
  coordinator.ts          两阶段导入状态机
  idbStore.ts             IndexedDB 存储（原子提交）
  memoryStore.ts          同语义内存实现（测试用）
src/features/exhibition/  启动引导、运行时展览、内置展览安装、自愈
src/features/exchange/    交换面板、导入预览、示例包、导出
tests/                    vitest 单元与集成测试（含 fake-indexeddb）
e2e/                      playwright 端到端测试
```

示例包（交换面板内一键生成）覆盖：正常导入、损坏讲解降级、
空间冲突、超出容量四种情形。
